# T-057 AI 模型可替换 + 备用模型自动兜底（含 API Key 后台录入）

> 用户 2026-10-25：「要添加可以随时更换 AI 提取地点的模型，未来用其他模型可以直接输入 API key 去更换；或者增加一个备用模型接口，万一当前模型无法使用，可以快速更换」。

## 1. 数据模型（`app_settings.ai`）

```ts
type LlmProvider = {
  label: string;      // 展示名，如 "DeepSeek" / "通义千问"
  baseUrl: string;    // 如 https://api.deepseek.com（不含 /chat/completions）
  model: string;      // 如 deepseek-chat
  apiKey: string;     // 仅服务端存储；空字符串表示回落到环境变量
  enabled: boolean;
};
ai: {
  primary: LlmProvider;             // 必须有
  fallback: LlmProvider | null;     // 可空
  ocrAction: OcrAction;             // 已有
  ocrRegion: string;                // 已有
}
```

- **兼容**：读取时若库里是旧结构（`deepseekModel`/`deepseekBaseUrl`），自动映射为 `primary`，下一次保存写新结构
- **密钥安全**：
  - `GET /api/admin/settings` 返回 `primary.apiKeyMask`（如 `sk-••••m3k9`）与 `hasApiKey: true`，**绝不返回明文**
  - `PATCH` 时 `apiKey` 省略/`""` = 保持不变；传 `null` = 清空（回落环境变量）
- **防 SSRF**（校验 baseUrl）：
  - 必须 `https://`
  - 禁止 `localhost` / `127.*` / `10.*` / `172.16-31.*` / `192.168.*` / `169.254.*` / `*.internal`
  - 只允许路径为空或 `/`

## 2. 运行时（`lib/llm.ts` 新增，`lib/deepseek.ts` 改为调用它）

- `chatJson<T>({ system, user })`：
  1. 用 `primary` 请求 `POST {baseUrl}/chat/completions`（OpenAI 兼容格式），`Authorization: Bearer {apiKey||env}`，超时 **45s**
  2. 失败判定（网络错误 / 非 2xx / 超时 / 内容不是合法 JSON）→ 若 `fallback` 已启用且配置完整，**重试一次** fallback
  3. 成功返回 `{ data, provider: 'primary'|'fallback' }`；全失败抛错（错误信息含两次失败原因，便于排查）
  4. 走 fallback 时 `console.warn('[llm] primary 失败，已切备用：<原因>')`
- `extractPlaces()` / `extractPlacesAndCity()` 的对外签名不变

## 3. 后台 UI（AI 模型区重做）

- **主模型卡**：模型名称 / Base URL / 模型名 / API Key（`type=password`，占位显示"已保存：sk-••••m3k9"）/ 启用 / `[测试连接]`
- **备用模型卡**（可启用/禁用）：
  - 未启用时显示「+ 添加备用模型」
  - 启用后同主模型字段 + `[测试连接]` + `[清除备用]`
- **当前生效** 摘要：
  - `主：DeepSeek · deepseek-chat`
  - `备用：通义千问 · qwen-plus（已启用/未启用）`
- 「测试连接」按钮：调用 `POST /api/admin/settings/test-llm {which:'primary'|'fallback'}`，服务端发一条 8 token 的 ping，返回 `{ok, ms, provider, error?}`；**Key 不出服务端**

## 4. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/PATCH | `/api/admin/settings` | 扩展 ai 段（掩码/校验） |
| POST | `/api/admin/settings/test-llm` | 测试连接（仅管理员） |

## 5. 验收标准

- [ ] 旧结构自动映射，保存后写新结构，无数据丢失
- [ ] GET 响应**不含任何明文 Key**（grep 响应体验证）
- [ ] 设置主模型为非法 baseUrl（http / 内网 IP）→ 400
- [ ] 「测试连接」主/备都能返回真实结果（成功显示 ms，失败显示原因）
- [ ] **兜底实测**：把主模型 baseUrl 改为不可达地址 → `/api/ai/extract` 仍成功（走备用），日志出现切换告警
- [ ] 关闭备用后主模型失败 → 接口返回明确错误（不静默）
- [ ] `typecheck` 0、`test:run` 全过、`test:e2e` 8 条通过
- [ ] 改完重启 dev 再截图（A8）

## 6. 测试方案（Harness）

1. GET 校验掩码；`grep -c "sk-" ` 响应体应为 0（除掩码格式）
2. 主/备各测一次连接
3. 主模型指向不可达域名 → 提取接口仍成功
4. 非法 URL 400
5. 恢复默认（主=DeepSeek，备用关闭）
