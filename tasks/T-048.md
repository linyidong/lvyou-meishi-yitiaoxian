# T-048 后台概览：本月图片 OCR 用量 + OCR 计数改为持久化

> 用户 2026-10-24 第 3 条。迁移 031 已由 Harness 执行（`user_daily_usage.kind` 允许 `ocr`）。

## 1. 目标

1. 后台概览页（`/admin`）新增「**本月图片 OCR 识别用量**」指标：本月已用次数 / 额度 / 剩余
2. OCR 计数从**内存 Map** 改为 **DB 持久化**（`user_daily_usage`，kind=`ocr`），修复 known-issues A9
3. 额度来源：新增配置 `BUSINESS.OCR_MONTHLY_QUOTA`（默认 **1000**，腾讯云通用印刷体免费额度量级；可在设置页后续接管）

## 2. 现状

| 项 | 现状 |
|---|---|
| `lib/ocr-usage.ts` | 进程内 `Map<userId, {day,count}>`，重启清零、多实例不共享（A9） |
| `/api/ai/extract-image` | 成功后 `bumpOcrUsage(userId)` |
| 后台概览 | 有高德用量卡片，无 OCR |
| `user_daily_usage` | `(user_id, day, kind, count)`，kind 约束已含 `ocr` |

## 3. 实现

### ① `lib/ocr-usage.ts` 改 DB
- `getOcrUsage(userId)`：读 `user_daily_usage` 当天该用户 `kind='ocr'` 的 `count`（无行=0）
- `bumpOcrUsage(userId)`：upsert（on conflict `(user_id, day, kind)` 累加 +1），返回累加后的值
- 保留 `ocrDailyLimit()`；新增 `getOcrMonthlyUsage()`：`sum(count)` where `kind='ocr'` and `day >= 本月 1 日`
- 服务端用 `createAdminClient()`（该表无用户写策略）；失败时**降级为允许**（不能因计数失败阻断识别），但要 `console.warn`

### ② 后台概览卡片
`app/admin/page.tsx`（或对应概览组件）在高德用量卡片旁/下方新增一张卡片：
- 标题「本月图片 OCR 识别用量」
- 主数字：`本月已用 N / 额度 M`，副文案：剩余 / 百分比
- 视觉与现有卡片一致（圆角、字号、颜色体系）

### ③ 配置
`config/business.ts` 增加 `OCR_MONTHLY_QUOTA: 1000`

## 4. 不做什么

- 不做设置页（另一个任务 T-049）
- 不改 OCR 接口的鉴权/大小限制
- 不删 `user_daily_usage` 其它 kind

## 5. 验收标准

- [ ] 调一次 OCR 成功后：`user_daily_usage` 出现/累加 `kind='ocr'`、`day=今天`、`count` 正确
- [ ] 第 21 次（日限 20）返回 **429**；计数落库为 21（或按实现说明）
- [ ] 后台概览显示「本月已用 N / 1000」，N 与实际一致
- [ ] 重启 dev server 后计数**不归零**（持久化生效）
- [ ] `typecheck` 0、`test:run` 全过、`test:e2e` 8 条通过
- [ ] 改完重启 dev 再截图（A8）

## 6. 测试方案（Harness）

1. 记录调用前 `count` → 调一次 OCR → 核对 `+1`
2. 重启 dev → 再查 → 计数仍在
3. 后台截图看卡片数字与库内一致

## 7. 失败恢复

`git revert <commit>`；`delete from user_daily_usage where kind='ocr'` 可清空 OCR 计数
