# T-060 会员导入分享路线：双入口（链接 / 二维码长图）→ 先预览 → 再选择动作

> 用户 2026-10-25：「会员导入其他会员的长图路线时，应该是选择链接和选择长图识别二维码的两个入口；导入之后先查看完导入的路线，再去选择『建成我的路线』还是『只收藏地点』」。

## 1. 现状

`components/share/ShareImportDialog.tsx`：粘贴链接/token → **当场**选「建成我的路线 / 只收藏地点」→ 提交。
用户希望：**先看路线，再决定**。

## 2. 目标流程

```
[导入分享路线]
 ├─ 入口 A：粘贴分享链接 / token
 └─ 入口 B：上传长图（含二维码）→ 自动识别 token
        ↓
   解析成功 → 预览页（路线标题 / 城市 / 天数 / 地点数 / 前若干个地点 / 分享时间）
        ↓
   [建成我的路线]（占额度）   [只收藏地点]（不占额度）   [关闭]
```

- 预览数据来自分享快照，**不消耗会员额度**
- 「建成我的路线」成功后跳新路线；「只收藏地点」后提示已收藏 N 个

## 3. 实现

### ① 二维码识别
- 上传图片（png/jpg/webp，≤7MB）后在前端解码出 URL/token
- 依赖：`jsqr`（纯 JS，MIT，约 30KB）；用 `createImageBitmap` + canvas 取 ImageData 传给 jsQR
- 识别结果用现有 `parseShareToken` 解析；失败提示「没识别到分享链接，请确认是长图右下角二维码」
- 长图里二维码通常较小：解码前把图片缩放到长边 ≤1200 再转灰度，必要时对中心区域裁剪重试

### ② 预览接口
- 新增 `GET /api/shares/[token]`（登录用户可访问）：
  - 返回 `{ ok, snapshot: { title, cityName, days, placeCount, places: 前 8 个 {name,type}, exportedAt } }`
  - 不写库、不占额度；404/410 处理失效分享
- 复用现有快照读取逻辑（`dayPlans` 结构）

### ③ 弹窗改三步
- `step: 'input' | 'preview'`
- input：两个 tab（链接 / 二维码），解析成功后 `GET /api/shares/:token` → 切 preview
- preview：卡片式展示 + 两个动作按钮（沿用 `POST /api/shares/:token/import` 的 `mode`）

## 4. 不做什么

- 不改分享页本身、不改额度规则
- 不做"未登录也能预览"（需登录，与现有一致）
- 不引入除 jsqr 外的依赖

## 5. 验收标准

- [ ] 弹窗有「链接」「二维码」两个入口
- [ ] 上传含二维码的长图能识别出 token 并进入预览
- [ ] 预览展示标题/城市/天数/地点数/前几个地点，且**未占用额度**（`user_daily_usage` 无新增）
- [ ] 预览后点「建成我的路线」→ 新建路线且额度 -1；点「只收藏地点」→ 收藏 +N、无新路线、不占额度
- [ ] 二维码识别失败有明确提示，不卡死
- [ ] 手机 390 弹窗不溢出
- [ ] `typecheck` 0、`test:run` 全过、`test:e2e` 8 条通过
- [ ] 改完重启 dev 再截图（A8）

## 6. 测试方案（Harness）

1. 造一个分享 token（用现有路线分享）→ 弹窗预览 → 两种动作各测一次并核对库
2. 用导出的长图（含二维码）测识别
3. 额度前后对比

## 7. 失败恢复

`git revert <commit>`；删除测试产生的路线/收藏

## 8. 风险等级

**中**（涉及额度与多步交互）
