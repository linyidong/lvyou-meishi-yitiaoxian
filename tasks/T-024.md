# T-024 阶段 8 验收：核心链路 E2E + 验收结果落档

> 由 Harness 起草。阶段 8「验收、部署与上线」的**验收部分**（部署本期不做）。

## 1. 目标

把核心链路扩成可重复执行的 E2E，跑一遍并把结果按四态（通过/失败/未执行/未覆盖）写进 `docs/acceptance-test-plan.md`。

## 2. 不做什么

- 不做部署、不写 CI
- 不改业务代码（发现 bug 另立任务）
- 不测支付真实到账（无商户号，人工核销仍是设计）

## 3. 需要覆盖的链路

| ID | 链路 | 断言要点 |
|---|---|---|
| E2E-01 | 管理员登录 → `/admin` | 登录成功、概览页渲染、无 500 |
| E2E-02 | 管理员 `/admin/routes` | 手机视口下显示卡片、桌面显示表格 |
| E2E-03 | 游客三步 → `/try/result` | 地图渲染、路线列表 ≥1 项、一键复位按钮存在 |
| E2E-04 | 游客点「保存路线」 | 跳转登录页且带 redirect 参数 |
| E2E-05 | 已登录用户 `/profile` | 会员卡渲染、显示档位 |
| E2E-06 | 未登录访问 `/routes` | 重定向到登录页 |

## 4. 凭据处理（重要）

- 账号密码只存放在 `Project/.env.test.local`（已在 `.gitignore`）
- 测试代码**只能从 `process.env.TEST_EMAIL / TEST_PASSWORD` 读取**
- 请在 `playwright.config.ts` 里加一个 loader：若存在 `.env.test.local` 则读入并挂到 `process.env`；不存在则相关用例 `test.skip`
- **不得**把密码写进测试文件、fixture、快照或任何仓库文件
- 不得在日志里打印密码

## 5. 涉及模块与允许修改的文件

| 文件 | 允许的改动 |
|---|---|
| `Project/tests/e2e/*.spec.ts`（新增） | 上述 6 条链路 |
| `Project/playwright.config.ts` | 加载 `.env.test.local`、按需跳过 |
| `docs/acceptance-test-plan.md` | 填 "实际结果/证据/状态" 列（四态） |
| `docs/progress.md`、`docs/handover/阶段7-编码-交接摘要.md` | 同步 |

## 6. 明确禁止

- 不得提交任何凭据
- 不得改业务代码（真发现 bug → 记录到 known-issues 并在汇报里列明）
- 不得为了让用例通过而放宽断言
- 不得跑 `npm run build`（dev server 在服务）

## 7. 验收标准

- [ ] 6 条 E2E 全部真实执行（通过，或失败并给出真实原因）
- [ ] 测试代码中无明文密码（grep 可验证）
- [ ] `.env.test.local` 不存在时，鉴权类用例 skip 而不是失败
- [ ] `docs/acceptance-test-plan.md` 的状态列按四态填写，每条有证据
- [ ] `npm run test:run`（单测）仍 30 passed
- [ ] 不跑 build
