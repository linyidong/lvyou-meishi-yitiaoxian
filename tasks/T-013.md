# T-013 修复 build 阻塞：服务端页面把组件函数当 prop 传给客户端组件

> 由 Harness 起草。来源：T-012 收尾时 `npm run build` 暴露的预渲染失败（此前被 lint error 挡住）。

## 1. 目标

让 `npm run build` 完整通过：消除 `Functions cannot be passed directly to Client Components` 导致的预渲染失败。

## 2. 不做什么

- 不改任何视觉、文案、交互、业务逻辑
- 不改 `AdminErrorState` 的样式（图标尺寸/颜色必须与现在完全一致）
- 不动其它 `'use client'` 组件的调用方式
- 不通过关闭预渲染（`export const dynamic = 'force-dynamic'`）来绕过——那会改变缓存行为
- 不改 `package.json`、不改 ESLint 配置

## 3. 背景与依据

- 报错：`/admin/orders` 预渲染失败 —— `Functions cannot be passed directly to Client Components`
- 根因（Harness 定位）：
  - `Project/components/admin/AdminState.tsx:1` 是 `'use client'`
  - `AdminErrorState` 的 props 为 `icon: LucideIcon`（`:71`），内部渲染 `<Icon className="mx-auto h-12 w-12 text-red-400" />`（`:81`）
  - 5 个**服务端**页面把组件函数当 prop 传进去：
    - `Project/app/admin/orders/page.tsx:78`（`icon={DatabaseZap}`）
    - `Project/app/admin/places/page.tsx:33`
    - `Project/app/admin/imports/page.tsx:31`
    - `Project/app/admin/users/page.tsx:70`
    - `Project/app/admin/online/page.tsx:67`（`icon={Unplug}`）
  - RSC 规则：服务端 → 客户端只能传可序列化值或 React 元素，**不能传函数/组件**
- 为什么现在才发现：`next build` 先跑 lint，T-012 之前一直死在 lint，预渲染根本没跑到。

## 4. 涉及模块与允许修改的文件

| 文件 | 允许的改动 |
|---|---|
| `Project/components/admin/AdminState.tsx` | `icon` prop 类型改为 `React.ReactNode`，渲染改为 `{icon}`（去掉内部 className） |
| 上述 5 个 `page.tsx` | 传参改为已渲染元素：`icon={<DatabaseZap className="mx-auto h-12 w-12 text-red-400" />}`（online 页用 `Unplug`） |
| `docs/known-issues.md`、`docs/progress.md`、`docs/handover/阶段7-编码-交接摘要.md` | 同步状态 |

## 5. 明确禁止的变更

- 不得删掉图标（视觉必须一致）
- 不得把 `AdminErrorState` 改成服务端组件后丢弃 `AdminRetryButton`（同文件里 `AdminRetryButton` 依赖 `useRouter`，必须留在客户端）
- 不得改其它页面
- 不得 `dynamic = 'force-dynamic'` 或 `export const revalidate`
- 不得顺手改 warning、不得格式化文件

## 6. 实施步骤

1. `AdminState.tsx`：`icon: LucideIcon` → `icon: React.ReactNode`；删除 `LucideIcon` 的 import（若别处不用）；`:81` `<Icon className="mx-auto h-12 w-12 text-red-400" />` → `{icon}`
2. 5 个页面：`icon={DatabaseZap}` → `icon={<DatabaseZap className="mx-auto h-12 w-12 text-red-400" />}`（online 用 `Unplug`）
3. 逐页确认 import 的图标仍被使用（避免 unused import）
4. `npm run lint`（期望 0 error）
5. `npm run build`（期望**完整成功**，贴输出尾部）
6. 若 build 再暴露**第三个**阻塞：停下报告，不要扩大范围

## 7. 验收标准

- [ ] 视觉不变：图标仍是 48×48、红色（`h-12 w-12 text-red-400`）
