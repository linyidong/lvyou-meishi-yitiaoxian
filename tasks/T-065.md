# T-065 开工自检脚本支持环境变量覆盖 + 去硬编码 IP

> 2026-11-08 触发：`desktop-vrd3hft` 主机名解析失败，Supabase 实际在 `192.168.1.10:8000`；`check:env` 只读 `.env.local`、提示里写死 `192.168.1.11`（Supabase）与 `192.168.1.12`（本机局域网 IP，实际是 `192.168.1.6`），导致自检误报且误导排查方向。

## 1. 目标

1. `check-env.mjs` / `check-schema.mjs` / `check-cities.mjs` 读取 Supabase 地址时**优先 `process.env.NEXT_PUBLIC_SUPABASE_URL`**，没有再回落到 `.env.local`（与 Next 的 env 优先级一致，`@next/env` 已实测 process.env 优先）；
2. 失败提示里的 IP 不再写死：从实际 URL 取 host；本机局域网 IP 用 `os.networkInterfaces()` 推导；
3. 输出里增加一行「配置来源：env / .env.local」，排查时一眼看出用的是哪份配置。

## 2. 不做什么

- 不修改 `.env.local`（密钥禁区）；
- 不改应用运行时代码；
- 不改 `audit:mobile` / `scan:water` / 业务代码。

## 3. 实现要点

- `loadEnv()` 返回值与 `process.env` 合并时，`process.env` 优先（只对 `NEXT_PUBLIC_SUPABASE_URL` 做覆盖说明）；
- 提示文案：`确认与 ${host} 在同一局域网`、`cd Project && npm run dev -- -H 0.0.0.0 -p 3000`（不再指定局域网 IP，改为运行时探测并打印）；
- 保持只读、零写入、失败退出码非 0。

## 4. 验收标准

- [x] 不带环境变量：行为与现在一致（读 `.env.local`）；
- [x] 带 `NEXT_PUBLIC_SUPABASE_URL=http://192.168.1.10:8000`：Supabase 探活走新地址并通过；
- [x] 提示中不再出现 `192.168.1.11` / `192.168.1.12` 写死值；
- [x] 覆盖模式下 `check:schema` **65 项全过**、`check:cities` 库内一致；
- [x] dev server 未起时仍报两项失败（本机 + 局域网），起了则通过；
- [x] `node --check scripts/check-env.mjs` 通过。

## 5. 回滚

`git revert <commit>`；单文件脚本。

## 6. 风险等级

**低**（仅开发期自检脚本，不参与运行时）。
