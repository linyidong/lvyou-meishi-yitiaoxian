# T-019 建立自动化测试体系（vitest + playwright）

> 由 Harness 起草。用户 2026-10-22 01:50 批准引入（含 playwright）。
> 本任务要改 `Project/package.json`（新增 devDependencies 与 scripts），属**已批准**操作。

## 1. 目标

建立可运行的测试骨架，并至少覆盖：
- **单元/组件层（vitest）**：会员四态判定、限流分桶、路线排序等**纯逻辑**，≥ 8 个用例
- **E2E 层（playwright）**：1 条冒烟（能打开首页与 `/city` 并渲染出内容），证明 E2E 链路可用

## 2. 不做什么

- 不写"为了通过而通过"的空断言
- 不改业务源码（除非某纯函数需要导出才能测——那时只加 `export`，不改逻辑）
- 不覆盖需要真实登录/支付的重链路（后续单独排）
- 不动 CI（本期不做 CI/CD）

## 3. 背景与依据

- 现状：`Project/package.json` scripts 只有 dev/build/start/lint/typecheck，**无 test**；全仓 0 测试文件
- 可测的纯逻辑（Harness 已确认存在）：
  - `Project/lib/member-quota.ts`：`isMemberActive` / `limitsOf` / `tierOf`
  - `Project/lib/guest-rate-limit.ts`：`checkGuestRateLimit` / `resolveGuestKey`（模块内 Map 状态，需 `vi.resetModules`）
  - `Project/lib/route-order.ts`：`orderByMatrix` 等
  - `Project/lib/route-share.ts`：`buildRouteSnapshot`（若依赖外部则跳过并说明）
- 参考：`docs/acceptance-test-plan.md` 已有用例 ID 体系（E-xx / T-xx），测试命名尽量对齐

## 4. 涉及模块与允许修改的文件

| 文件 | 允许的改动 |
|---|---|
| `Project/package.json` | devDependencies：`vitest`、`@vitejs/plugin-react`、`jsdom`、`@testing-library/react`、`@testing-library/jest-dom`、`@playwright/test`；scripts：`test`、`test:run`、`test:e2e` |
| `Project/vitest.config.ts`（新建） | 别名 `@/*` → `./`，environment jsdom |
| `Project/playwright.config.ts`（新建） | `webServer` 复用已有 dev（或自行启动 3100 端口） |
| `Project/tests/unit/*.test.ts`（新建） | ≥ 8 个用例 |
| `Project/tests/e2e/smoke.spec.ts`（新建） | 1 条冒烟 |
| `Project/.gitignore` | 忽略 `test-results/`、`playwright-report/` |
| `docs/progress.md`、`docs/handover/阶段7-编码-交接摘要.md` | 同步 |

## 5. 明确禁止的变更

- 不得为通过测试而修改业务逻辑或放宽断言
- 不得引入除上述以外的依赖（不引 jest、不引 cypress）
- 不得把测试写进 `app/` 目录（避免被 Next 当作路由）
- 不得改动生产构建配置

## 6. 实施步骤

1. 安装 devDependencies（`npm i -D ...`），确认 `npm ls` 无冲突
2. 写 `vitest.config.ts`（别名与 jsdom）
3. 写 ≥ 8 个单元用例，至少覆盖：会员四态（admin/永久/有效/过期）、`limitsOf` 各档位、限流分桶（city-places vs order 的上限不同）、`checkGuestRateLimit` 达到上限返回 ok=false
4. 写 1 条 playwright 冒烟：访问首页与 `/city`，断言有标题或城市卡片
5. `npx playwright install chromium` 安装浏览器
6. 跑 `npm run test:run` 与 `npm run test:e2e`，贴真实输出
7. 若 E2E 因环境（沙箱/端口/中文路径）失败，如实报告并给出可行的替代（如仅跑浏览器安装验证）

## 7. 验收标准

- [ ] `npm run test:run` 全部通过（贴输出，含用例数与耗时）
- [ ] 用例数 ≥ 8，且**至少 3 个模块**被覆盖
- [ ] `npm run test:e2e` 至少 1 条通过（或用例真实执行并给出失败原因）
- [ ] 测试文件不在 `app/` 下
- [ ] `.gitignore` 忽略测试产物
- [ ] 未改业务逻辑（`git diff` 里 `app/`、`components/` 无改动；如需导出纯函数，仅加 `export`）
- [ ] `npm run typecheck` 仍 exit 0

## 8. 自动化测试

本任务本身就是自动化测试建设；验收以 `npm run test:run` / `test:e2e` 的真实输出为准。

## 9. 人工验收

用户：`cd Project && npm run test:run` 能自己跑通；`npm run test:e2e` 能跑（首次需已装 chromium）。

## 10. 失败恢复

`git revert <commit>` + `npm uninstall`（依赖回滚）；测试不影响生产构建。

## 11. 风险等级

**中**：改 `package.json` 与 node_modules，可能影响 dev server（必要时重启 dev）。
