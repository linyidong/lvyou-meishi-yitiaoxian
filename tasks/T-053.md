# T-053 AI 模型可配置：DeepSeek 模型/地址 + OCR 接口类型

> 用户 2026-10-25 第 4 条（拆分第 3 个任务）。目标：以后能在后台改 AI 模型并立即生效，不用改代码。

## 1. 目标

设置页「AI 模型」区新增可配置项，保存后**真实生效**：

| 字段 | 类型 | 默认 | 生效位置 |
|---|---|---|---|
| DeepSeek 模型名 | 文本 | `deepseek-chat` | `lib/deepseek.ts` 请求体的 `model` |
| DeepSeek API 地址 | 文本（URL） | `https://api.deepseek.com` | 拼接 `/chat/completions` 后作为请求地址 |
| OCR 接口 | 下拉：`通用印刷体(GeneralBasicOCR)` / `高精度(GeneralAccurateOCR)` | GeneralBasicOCR | `lib/tencent-ocr.ts` 的 `X-TC-Action` |
| OCR 地域 | 文本 | `ap-guangzhou` | 已有，保持不变 |

- 校验：URL 必须 http(s)；模型名非空、长度上限；OCR 接口只允许两个枚举值
- 保存后 30s 内生效（沿用现有缓存），页面提示"保存后立即生效（最多 30 秒）"

## 2. 实现要点

- `lib/app-settings.ts`：`ai` 增加 `deepseekBaseUrl`、`ocrAction`；默认值、补丁校验、合并逻辑同步
- `lib/deepseek.ts`：改为从 `getAppSettings()` 读取 model 与 baseUrl（服务端调用，async 可用）；请求 URL = `${baseUrl}/chat/completions`（去掉末尾斜杠）
- `lib/tencent-ocr.ts`：`X-TC-Action` 改为从设置读取；`ocrImageBase64` 已是 async
- `SettingsForm`：AI 区加两个字段（Base URL 输入框、OCR 接口下拉），沿用现有样式
- 摘要区（当前生效配置）同步展示：`DeepSeek · {model} @ {baseUrl}`、`腾讯云 OCR · {action}`

## 3. 不做什么

- 不接入其它厂商（只做"可配置"，不做多供应商切换）
- 不改 OCR 签名算法与鉴权
- 不改配额与开关逻辑
