# T-028 会员价格与配额调整 + 会员状态实时同步

> 用户 2026-10-23 23:22：① 会员改 9.9 元/月、每月可生成 5 次路线（手机与电脑同步）；② 后台取消会员后，用户端立即自动刷新状态与身份。

## 1. 目标

### ① 价格与配额
- 月卡价格：`1500` 分 → **`990` 分（¥9.9）**
- 会员每月可生成路线：`10` → **`5` 条**
- 文案、权益说明、后台展示同步（不得残留"10 条""15 元"）
- 手机与电脑共用同一份配置（改配置即两端一致，不得各写一份）

### ② 会员状态自动同步（无需手动刷新）
- 管理员在后台**取消会员**（或开通）后，用户端页面在 **≤20 秒**内自动更新：
  - 顶部身份（会员徽标 / 普通用户）
  - 个人中心会员卡
  - 配额展示与限制（服务端按新身份判定）
- 实现方式：新增轻量 `GET /api/member/status`（只读本人 `member / member_until / role`）+ 客户端轮询组件，状态变化时 `router.refresh()`
- 不得使用 Supabase Realtime（本项目未启用该服务）

## 2. 不做什么

- 不改订单流程与核销逻辑
- 不改管理员默认最高级会员的规则（`015` 触发器 / `ADMIN_MEMBER_FIXED`）
- 不改其它档位（仅月卡）
- 不引入新的第三方依赖
- 不动 admin 其它页面

## 5. 明确禁止

- 不得在组件里硬编码 `9.9` 或 `5`（必须来自配置）
- 不得让两端（手机/电脑）出现不同价格
- 不得轮询过密（<10s）或对未登录用户轮询
- 不得用 Realtime / WebSocket 新增依赖
- 不得改订单金额计算逻辑以外的计费规则

## 6. 实施步骤

1. 改 `business.ts` 两处配置；全局搜索 `1500`、`10 条`、`MEMBER_MONTHLY_ROUTE_LIMIT` 清理残留
2. 新增 `GET /api/member/status`：`getUser()` → 401 或查 `users` 本人行 → 返回三字段（`cache: no-store`）
3. 新增 `MemberStatusSync` 客户端组件：`setInterval(20_000)`、`document.visibilitychange`、`window.focus` 触发；比较 `member/memberUntil` 变化 → `router.refresh()`
4. 在 `app/(user)/layout.tsx` 挂载（仅当有登录用户时）
5. 补单测：`limitRoutesOf` 对会员返回 5；`MEMBER_PLANS[0].priceCents === 990`
6. 文案与文档同步
