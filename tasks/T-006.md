## 1. 目标

`/route/[id]`（普通/会员路线详情页）提供与 T-005 一致的「一键复位」：手动调序后一键还原到进入页面时的系统推荐顺序，零接口请求。

## 2. 不做什么

- **不触发系统重排**（不调 `syncRoute`、不调任何 order 接口）；复位只允许触发一次既有的 `saveOrder()` 落库
- 不占游客/会员的「生成路线」额度（不碰高德距离矩阵）
- 不合并两套结果页组件（用户明确保留）
- 不动 dnd-kit 既有拖拽逻辑、不动 `SortablePlaceRow` 的排序行为
- 不改 `/api/amap/order`、`/api/routes/*`
- 不新增 state 触发重排（D-04）

## 5. 明确禁止的变更

- 网络：复位路径内只允许经由既有 `saveOrder()`（防抖 PUT `/api/routes/[id]/places`）落库，**不得新增其它 fetch**
- 状态：不得 `setState` 触发依赖顺序的 effect 重跑（D-04）
- 不得改保存逻辑（复位≠保存，保存仍需用户显式触发）
- 不得升级依赖、不得夹带重构、不得格式化整文件

## 6. 实施步骤

1. 计划阶段先确认：此页「系统初始顺序」到底是挂载时的 `route_places` 顺序，还是最近一次 order 响应——用行号说明
2. 挂载/首次数据到达时快照
3. 派生 `orderDirty`（与快照比对）
4. `resetOrder()`：还原 points 与相关派生数据（分段里程/总里程若依赖 points 需一并还原）
5. 复位末尾调用既有 `saveOrder()`（复用防抖落库，不新增请求逻辑）
6. 按钮常驻 + `disabled` 条件
7. typecheck + dev 实测页面 200

## 7. 验收标准

- [ ] 未调序时按钮 disabled
- [ ] 调序后按钮可用
- [ ] 复位后顺序 = 进入页面时顺序（含住宿点位置）
- [ ] 复位期间 Network 无新请求
- [ ] 复位后 Network 出现 **1 次** `PUT /api/routes/[id]/places`（不出现 `/api/amap/order`、不出现系统重排）
- [ ] 复位后**直接离开再重进**，显示的是复位后的顺序（因为已落库）
- [ ] 复位后点保存，库内顺序 = 复位后顺序
- [ ] typecheck exit 0
- [ ] 未新增 fetch、未改保存逻辑、未改 `/api/*`
