# T-020 修复 R1 + R2：保存点位原子化 + 核销 CAS

> 由 Harness 起草。来源：`docs/concurrency-audit.md` R1（高，含数据丢失）/ R2（中）。
> 用户 2026-10-22 12:45 决定：R1 与 R2 一起修。
> 本任务涉及一次 DDL 迁移（加唯一约束 + 建函数），已获批准。

## 1. 目标

1. **R1**：`PUT /api/routes/[id]/places` 的「删除 + 插入」变成**单个数据库事务**；插入失败时原数据**不被清空**；并发写不产生重复行。
2. **R2**：核销接口的「读-判-写」变成**原子占用**，重复点击/并发点击只会有一次生效，不会重复写 `member_logs`、不会重复刷 `member_since`。

## 2. 不做什么

- 不改 UI 交互（除失败提示文案）
- 不改配额数字、不改会员天数计算规则
- 不改其它接口
- 不做 R3/R4（下单软上限、建路线配额），另立任务

## 3. 背景与依据

**R1**（`docs/concurrency-audit.md` §0、§3）
- `Project/app/api/routes/[id]/places/route.ts:108-121`：`.delete()` 与 `.insert()` 两次独立请求，无事务
- 失败路径：delete 成功 + insert 失败 → 返回 500，但 `route_places` 已被清空（**数据丢失**）
- 数据库：`pg_indexes` 显示 `route_places` 只有 pkey 与普通索引 `(route_id, day_index, order_index)`，**无唯一约束** → 并发可插重复行

**R2**（`docs/concurrency-audit.md` §2）
- `Project/app/api/admin/member/orders/[id]/route.ts`：`:55` 读订单 → `:61` 判 `pending` → `:89` 改 `users` → `:100` 写 `member_logs` → `:110` 改订单状态
- 并发/重放：两个请求都读到 pending → 都写 logs、都刷 `member_since`

## 6. 实施步骤（建议）

1. **迁移 027**
   - `alter table route_places add constraint route_places_slot_uniq unique (route_id, day_index, order_index);`
     （先检查是否存在重复数据，有则先说明、不强行加）
   - `create or replace function replace_route_places(p_route_id uuid, p_items jsonb) returns integer language plpgsql security definer as $$ ... $$`
     函数体内：`delete from route_places where route_id = p_route_id;` → `insert ... select from jsonb_to_recordset(...)` → return 插入行数；整体在一个事务内
2. 路由改为 `supabase.rpc('replace_route_places', { p_route_id, p_items })`；失败返回 500 但**数据未被清空**
3. 客户端 `saveOrder`：非 2xx 时 toast「保存失败，已保留原顺序」并恢复/保留本地顺序
4. **R2**：核销先做原子占用
   ```ts
   const { data: claimed } = await admin.from('member_orders')
     .update({ status: 'approved', reviewed_at: now, reviewed_by: adminId })
     .eq('id', id).eq('status', 'pending').select('id')
   if (!claimed?.length) return 409 // 已被处理
   ```
   然后再改 `users` 与写 `member_logs`；若后续步骤失败，需回写订单状态并说明补偿逻辑
5. 验证（见 §8）
