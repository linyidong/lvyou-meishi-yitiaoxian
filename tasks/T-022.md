# T-022 修复移动端整页被撑宽（Grid 子项 min-width:auto）

> 由 Harness 起草。用户反馈「手机页面不适配、字要放大、要左右拖」。
> **Harness 已用 Playwright 定位并验证修法**（注入样式测试），不是猜测。

## 1. 目标

消除「内容比屏幕宽 → 浏览器整体缩小页面」的问题：手机上 `window.innerWidth == visualViewport.width`，用户不再需要放大/左右拖。

## 2. 现象与根因（实测证据）

- 页面：`/try/pick`（有草稿的真实状态）
- 实测：`innerWidth = 551`、`visualViewport.width = 402`、`scrollWidth = 551`
  → 内容宽 551，浏览器为适配把整页缩小到 402，**文字随之变小 27%**
- 根因：外层 `grid`（`components/try/TryPickClient.tsx:406` `<div className="mt-6 grid gap-6 lg:grid-cols-3">`）的子项默认 `min-width: auto`，被内部内容的 min-content（535px）撑开，网格列宽变成 534.95px，溢出容器（370px）
- **验证**：向该页注入 `.mt-6.grid > * { min-width: 0 }` 后，`innerWidth` 立即从 551 → **402**，`scrollWidth` 402，无残留超宽元素

## 3. 不做什么

- 不改视觉风格、不改文案、不改业务逻辑
- 不改桌面断点（`lg:grid-cols-3` 保留）
- 不引新依赖
- 不动 admin 页面

## 4. 涉及模块与允许修改的文件

| 文件 | 允许的改动 |
|---|---|
| `Project/components/try/TryPickClient.tsx` | 给 grid 子项（`section`、`aside`）加 `min-w-0` |
| `Project/components/route/RoutePlacesClient.tsx`、`RouteAddClient.tsx`、`RouteEditClient.tsx`、`HomeClient.tsx` 等 | 同样的 `grid ... lg:grid-cols-*` 容器，子项补 `min-w-0`（用 grep 找全） |
| `Project/scripts/mobile-audit.mjs` | 如需微调判定（已有流程测量，尽量不改） |
| `docs/progress.md`、`docs/known-issues.md`、`docs/handover/阶段7-编码-交接摘要.md` | 同步 |

## 5. 明确禁止

- 不得用 `overflow-x: hidden` 掩盖问题（那只是把溢出藏起来，内容仍被裁）
- 不得改 viewport meta、不得用 transform scale
- 不得整文件格式化

## 6. 实施步骤

1. `grep -rn "lg:grid-cols-3\|md:grid-cols-2" components/` 列出所有 grid 容器
2. 给这些 grid 的**直接子元素**加 `min-w-0`（grid item 收缩所需）
3. 检查子元素内部是否还有 `flex` 不换行导致撑宽（补 `flex-wrap` 或 `min-w-0`）
4. 跑 `npm run audit:mobile`，确认两条「流程」用例通过（挑选地点与结果页宽度正常、地图 ≥40% 视口）
5. 手动确认「生成路线」按钮可点击（此前因整页缩放导致点击落点错位）
