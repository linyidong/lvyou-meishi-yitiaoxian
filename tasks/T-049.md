# T-049 后台「设置」与「技术栈」两个页面

> 用户 2026-10-24 第 4 条。范围：**B（AI 模型 + 业务开关 + 配额数字）**。

## 1. 目标

后台侧边栏在「会员订单」下方新增两项：**设置**、**技术栈**。

### ① 设置页 `/admin/settings`
三个分组，可编辑并保存到 `app_settings`（迁移 032 已建表，key='global'，RLS 无策略=仅 service_role）：

| 分组 | 字段 | 默认值来源 |
|---|---|---|
| AI 模型 | DeepSeek 模型名（默认 `deepseek-chat`）、OCR 地域（默认 `ap-guangzhou`）、OCR 月额度（默认 1000） | `BUSINESS.OCR_MONTHLY_QUOTA` |
| 业务开关 | 开放付费（`billingEnabled`）、图片识别（`ocrEnabled`）、导入地点（`importEnabled`） | 付费当前为 true |
| 配额数字 | 正常用户单日地点（12）、会员单日地点（12）、会员每月路线（5）、AI 提取·正常（10）/会员（20）、OCR 每日次数（20） | `config/business.ts` |

- 保存后**尽量即时生效**（见下"应用点"）；表单需校验数字范围（正整数，合理上限）
- 页面顶部说明「保存后立即生效；个别数字下次请求生效」

### ② 应用点（必须真正生效，不能只存不用）
| 设置 | 生效位置 |
|---|---|
| billingEnabled=false | `POST /api/member/orders` 返回 403（同现有内测拦截口径） |
| ocrEnabled=false | `POST /api/ai/extract-image` 返回 403 |
| importEnabled=false | `POST /api/ai/extract`、`POST /api/places` 返回 403 |
| ocrDailyLimit | OCR 接口日限判定 |
| ocrMonthlyQuota | 后台概览 OCR 卡片的分母 |
| freePlacesPerDay / memberPlacesPerDay | `PUT /api/routes/[id]/places` 的单日上限判定 |
| memberMonthlyRoutes | `getRouteQuota` 的会员每月上限 |

### ③ 技术栈页 `/admin/tech-stack`
- **先做页面骨架**：分组展示（前端 / 后端 / 数据 / 地图与算路 / AI 与外部服务 / 部署与运维），每组留 3–6 条占位条目（内容待产品提供截图后补充）
- 顶部注明「内容待补充」
- 结构与后台其它页一致（AdminShell、面包屑）

## 2. 不做什么

- 不改前台页面
- 不做按用户的个性化设置（全局一份）
- 不改现有配额默认值（只做可覆盖）
- 技术栈内容不编造具体版本号以外的信息

## 3. 验收标准

- [ ] 侧边栏「会员订单」下出现「设置」「技术栈」，点击进入对应页
- [ ] 设置页可保存并在刷新后保留（DB 持久化）
- [ ] 关闭「开放付费」→ 下单接口 403；恢复后正常
- [ ] 关闭「图片识别」→ OCR 接口 403；恢复可用
- [ ] 把 OCR 日限改成 1 → 第 2 次识别 429；改回 20 恢复
- [ ] 后台概览 OCR 卡片的额度分母随 `ocrMonthlyQuota` 变化
- [ ] 技术栈页骨架可访问、无 500
- [ ] 非管理员访问 `/admin/settings`、`/admin/tech-stack` → 跳登录/拒绝
- [ ] `typecheck` 0、`test:run` 全过、`test:e2e` 8 条通过
- [ ] 改完重启 dev 再截图（A8）

## 4. 测试方案（Harness）

1. 保存 → 刷新 → 值仍在（DB 校验 `app_settings`）
2. 逐项开关：付费/OCR/导入 三个 403 实测，再恢复
3. OCR 日限改 1 → 429 实测 → 改回
4. 概览分母变化截图
5. 非管理员访问两个新页

## 5. 失败恢复

`git revert <commit>`；`delete from app_settings where key='global'` 恢复默认

## 6. 风险等级

**中**（设置会改变线上行为，必须实测开关）
