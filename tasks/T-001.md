# T-001 A5 修复：删死接口 + landmarks 加登录校验

> 由 Harness 起草，与 `docs/implementation-plan.md` T-001 对应。用户已批准计划（G5，2026-10-21 01:00），**范围确认后**方可实施。

## 1. 目标

关闭两个匿名可调、会直接烧高德额度的代理接口：删除无任何调用方的 `/api/amap/search`；给 `/api/amap/landmarks` 加登录校验。

## 2. 不做什么

- 不动 `Project/lib/amap.ts` 的 `searchPlaces` 本体（服务端内部仍被 `api/places`、`api/admin/seed-demo` 使用）
- 不改 landmarks 的熔断判断（`isAmapQuotaCritical`）与缓存逻辑
- 不给这两个接口加游客限流桶（本任务只做鉴权，限流是另一件事）
- 不顺手改其他 `api/amap/*` 接口
- 不新增环境变量、不改 `package.json`

## 3. 背景与依据

- PRD 条目：`docs/项目需求文档PRD.md` §4.1 修复-A5、§10 安全
- 现状证据：
  - `Project/app/api/amap/search/route.ts:9` POST 全文无 `getUser`、无限流
  - `Project/app/api/amap/landmarks/route.ts:27` POST 无 `getUser`，仅 `:53` 有额度熔断
  - `Project/middleware.ts` 对 `/api/*` 一律放行（只在页面路由做重定向）
  - `/api/amap/search` 无任何调用方（`grep -rn "amap/search"` 零命中，已两次复核）
  - `/api/amap/landmarks` 仅被 `Project/components/route/RouteResultClient.tsx:1119` 调用，所在页面 `/route/[id]` 受登录保护
- 已知问题：`docs/known-issues.md` A5
- 决策记录：`docs/decisions.md` D-010；`docs/open-questions.md` Q-001（用户 2026-10-21 拍板）

## 5. 明确禁止的变更

- 不得删除现有模块、功能、校验或测试（本任务唯一允许的删除是那个零调用的死接口）
- 不得更换公共接口签名（landmarks 的入参/出参保持不变，只加 401 分支）
- 不得升级依赖、执行数据库迁移
- 不得夹带无关重构或格式化
- 不得修改本任务范围外的配置

## 6. 实施步骤

1. 复核零调用方：`grep -rn "api/amap/search" Project/app Project/components Project/lib`，把输出贴进汇报
2. 删除 `Project/app/api/amap/search/` 目录
3. `landmarks/route.ts`：引入 `createClient`，在读取 body 之前 `const { data: { user } } = await supabase.auth.getUser()`；无 user → 401 + `MESSAGES.LOGIN_FIRST`
4. `npm run typecheck`
5. 起 dev server 取证：
   - 匿名 POST `/api/amap/landmarks` → 期望 **401**
   - 匿名 POST `/api/amap/search` → 期望 **404**
   - 登录态 POST `/api/amap/landmarks` → 期望 **200 且返回地点列表**
6. 关 dev server，`git status` 复核只改了上述文件
