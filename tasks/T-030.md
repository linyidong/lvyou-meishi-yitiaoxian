# T-030 一键启动项目（macOS 双击启动器）

> 用户 2026-10-24：不想每次让 Harness 帮忙起 dev server，要一个自己双击就能启动、自动打开页面的快捷方式。

## 1. 目标

在项目根目录提供三个文件，用户双击 `启动项目.command` 即可：

1. 自动切到 `Project/`
2. 若 3000 已在跑 → **直接打开浏览器**（不重复启动）
3. 若未跑 → 先跑 `npm run check:env`（失败只警告，不阻塞）
4. 启动 `npm run dev -- -H 0.0.0.0 -p 3000`
5. 等端口就绪后**自动打开** `http://localhost:3000`
6. 终端窗口保留日志（可看到报错/热更新）
7. 启动完成后打印**手机访问地址**（局域网 IP:3000）

另提供：
- `停止项目.command`：停掉 dev server（只杀本项目进程，不误杀其它 node）
- `make-shortcut.sh`：在桌面生成一个可双击的 `启动项目.app`（用 `osacompile`，图标可选）

## 2. 不做什么

- 不改应用代码、配置、依赖
- 不做开机自启（launchd 另行讨论）
- 不启动/管理 Supabase（Windows 上那台，脚本只做探活提示）
- 不动 `deploy/` 下的部署脚本

## 3. 现状（Harness 实测）

| 项 | 值 |
|---|---|
| 代码目录 | `Project/`（根目录下） |
| dev 命令 | `npm run dev -- -H 0.0.0.0 -p 3000` |
| 本机局域网 IP | `192.168.1.6`（`ipconfig getifaddr en0` 可取，可能变化） |
| 环境自检 | `npm run check:env`（4 项，失败会非 0 退出） |
| Supabase | `192.168.1.11:8000`（另一台 Windows，可能没开机） |

## 4. 允许修改/新增的文件

| 文件 | 说明 |
|---|---|
| `启动项目.command`（新增，根目录） | 主启动器，`chmod +x` |
| `停止项目.command`（新增，根目录） | 停止器 |
| `make-shortcut.sh`（新增，根目录） | 桌面 .app 生成脚本 |
| `docs/setup-and-run.md` | 追加「一键启动」小节 |
| `docs/progress.md`、`docs/handover/阶段7-编码-交接摘要.md` | 同步 |

## 5. 明确禁止

- 不得用 `pkill -f node`（会误杀其它 node 进程）；停止脚本必须精确匹配本项目的 next dev
- 不得把 dev server 放到后台后立即退出（用户要能看日志）
- 不得硬编码会变的 IP（用 `ipconfig getifaddr en0 || en1` 动态取，取不到就提示手动查）
- 不得依赖未安装的工具（只用 macOS 自带：bash / curl / lsof / open / osacompile）

## 6. 验收标准

- [ ] 双击 `启动项目.command`：若未运行 → 启动并自动打开浏览器（无需手动敲命令）
- [ ] 若已在运行 → 只打开浏览器，不报端口占用错误
- [ ] 启动后打印本机与手机访问地址
- [ ] `停止项目.command` 能停掉，且不误杀其它 node 进程
- [ ] `make-shortcut.sh` 能在桌面生成可双击的 .app
- [ ] Supabase 未开机时：脚本给出清晰提示（不闪退）

## 7. 测试方案（Harness 验收时执行）

1. 杀掉现有 dev server → 运行启动器 → 检查端口就绪 + 浏览器打开 + 页面 200
2. 再次运行 → 应识别"已在运行"并只开浏览器
3. 运行停止器 → 端口释放
4. `git status` 确认只新增上述文件

## 8. 失败恢复

删除新增的两个 `.command` 与 `make-shortcut.sh` 即可，无副作用。

## 9. 风险等级

**低**（仅新增本地脚本，不碰应用代码）。
