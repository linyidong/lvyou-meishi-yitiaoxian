# T-018 后台用户列表显示会员到期状态

> 由 Harness 起草。来源：PRD §4.1「会员到期后台不可见」+ `docs/known-issues.md` + 用户 Q7 决策（2026-10-21）。

## 1. 目标

后台用户列表把会员状态分三态显示：**永久会员 / 有效会员（显示到期日）/ 已过期**，并让"已过期"用户不再被误当成会员。

## 2. 不做什么

- 不改数据库、不写库（定时写回属 T-004，本任务只做"显示与判定"）
- 不改会员到期判定函数 `lib/member-quota.ts:78 isMemberActive` 的语义
- 不改核销流程与订单逻辑
- 不改用户端个人中心

## 3. 背景与依据

- `Project/app/admin/users/page.tsx:23` 的 select **没有 `member_until`**，`AdminUserItem` 也没有该字段
- `Project/components/admin/AdminUsersClient.tsx:63` `return u.member || u.role === USER_ROLE.ADMIN;` —— **直读 member，不判到期**，所以过期用户仍显示为会员、按钮仍是「取消会员」
- `lib/member-quota.ts:78` 有现成的 `isMemberActive(role, member, memberUntil)`（纯函数，可在客户端复用）
- 用户 Q7：要能看到"已过期"

## 4. 涉及模块与允许修改的文件

| 文件 | 允许的改动 |
|---|---|
| `Project/app/admin/users/page.tsx` | select 增加 `member_until`；映射进 `AdminUserItem` |
| `Project/components/admin/AdminUsersClient.tsx` | 三态徽章 + 过期用户的按钮语义 |
| `Project/config/messages.ts` | 新增三态文案（不改既有语义） |
| `docs/progress.md`、`docs/handover/阶段7-编码-交接摘要.md` | 同步 |

## 5. 明确禁止的变更

- 不得写库、不得改 `users` 表数据
- 不得改 `isMemberActive` 实现
- 不得把管理员（role=admin）判成"已过期"
- 不得整文件格式化

## 6. 实施步骤

1. `admin/users/page.tsx`：select 加 `member_until`，映射为 `memberUntil`
2. `AdminUsersClient`：用 `isMemberActive(role, member, memberUntil)` 得到"是否为有效会员"，再派生三态：
   - `role === admin` → `永久 / 管理员`
   - `member && memberUntil === null` → `永久会员`
   - `member && 未到期` → `会员 · 到期 YYYY-MM-DD`
   - `member && 已到期` → **`已过期`**（灰色/琥珀色徽章）
3. 按钮语义：已过期用户的「取消会员」→ 改为「已过期」（禁用）或「续期」提示（按现有交互最小改动，说明你的选择）
4. 徽章配色：有效=绿色系，永久=紫色系，已过期=琥珀/灰色系

## 7. 验收标准

- [ ] 列表能看到 `member_until`（无该字段时不崩，显示"—"）
- [ ] 三态徽章正确：管理员/永久会员/有效会员（带到期日）/已过期
- [ ] 过期用户不再显示为"会员"，不再出现误导性的「取消会员」可点按钮
- [ ] `npm run typecheck` exit 0（**不要跑 build**）
- [ ] 不写库（`git diff` 无 SQL/接口改动）
