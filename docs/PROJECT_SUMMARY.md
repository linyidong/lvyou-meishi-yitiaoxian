# 项目总结与复盘

> 收尾产出。范围：2026-10-20 接手 → 2026-10-22（内测阶段）。所有数字与结论均可在 `docs/` 内追溯。

## 1. 一句话介绍

「旅行美食一条线」是一个面向自助旅行者的**自动路线规划工具**：选城市 → 设行程 → 挑地点（库内 + 导入）→ 系统按就近不绕路排序 → 地图与分段里程 → 保存/分享；商业上采用游客试用 → 注册 → 会员付费的转化路径。

- 接手时状态：已有可运行代码（Next.js + 自建 Supabase），但无测试、文档散落在 `File-PRD/`、有一批未提交改动、无部署产物
- 本次目标（用户确认）：**付费转化优先**；本期 = 修缺陷 + 打磨转化链路 + 补核心链路测试；成功标准 = **真实跑通 1 轮付费链路**
- 未做：生产部署、CI/CD、年卡、付款自动回调

## 5. 系统架构与数据流（一句话版）

单体 Next（App Router）→ 服务端组件/Route Handler → Supabase（PostgREST/GoTrue）→ Postgres；高德与 DeepSeek 由 `lib/` 封装，带缓存与 Key 池。详见 `docs/architecture.md`。

核心链路（4 条）：游客生成路线、保存转正、会员订单核销、登录鉴权（`docs/module-map.md` §3）。

## 6. 核心模块

- `lib/member-quota.ts`：档位与配额（**14 个调用方**，全站单点）
- `lib/guest-rate-limit.ts`：免登录限流，**按接口成本分桶**（3/100/60 次每日）
- `lib/amap.ts`：Key 池、距离矩阵、算路、缓存
- `lib/route-order.ts`：最近邻 + 2-opt 排序
- `lib/route-poster.ts`：客户端 canvas 出图（不调高德静态图）
- `lib/supabase/*`：四种运行环境的客户端工厂

## 7. 关键技术问题及解决过程（真实案例）

### 7.1 保存点位可能清空用户路线（数据丢失）

- 现象：`PUT /api/routes/[id]/places` 先 `delete` 再 `insert`，两次独立请求
- 根因：无事务；insert 失败只回 500，但地点已被删光
- 解决：迁移 027 —— `replace_route_places()` 单事务函数 + 双口径唯一约束
- 验证：注入非法 `place_id` → 回滚后**仍有 19 行**（旧逻辑会变 0）
- 附带发现：两个 RPC 因 Supabase **默认权限**对 `anon` 可执行 → 匿名可调核销函数自开会员；已显式撤权，匿名调用 401

### 7.2 移动端"字小、要放大、要左右拖"

- 表面判断：以为没做响应式
- 实测（Playwright 真机尺寸）：`innerWidth 551` vs `visualViewport.width 402`
- 根因：CSS Grid 子项默认 `min-width:auto`，被内容 min-content 撑到 535px → 浏览器**整体缩小 27%**
- 解决：子项 `min-w-0`（注入验证后实施，18 个组件）
- 教训：**审计脚本必须走真实状态**（空页面不暴露溢出）

### 7.3 一个"看起来是 bug"的需求

- 用户截图批注「游客模式下骑行/公交/驾车是灰色、无法点击」被我读成报障
- 实际是**期望行为**；修正后加了 `disabled` + 说明文案
- 教训：批注先分清"现状描述"还是"期望状态"，不确定先问

### 7.4 我自己的一次误报（差点删功能）

- 我用 `grep -c "name: "` 得出"城市 104 个 vs 库内 92"，判定为缺陷
- Trae 的只读理解闸门(D1)质疑口径；用 TS 编译器求值 `CITIES` → **92**，与库、迁移完全一致
- 影响：若未拦截，任务卡会去"删掉 12 个不存在的多余城市"
- 后续：`npm run check:cities` 用 AST + 双向集合比对固化

## 8. 产品亮点

1. **游客零注册走完整流程**，只在"保存"处要求登录（转化漏斗更短）
2. **限流按接口成本分桶**：只读 100 次/日、重排 60 次/日、花钱接口 3 次/日
3. **一键复位**：零请求还原系统推荐顺序（游客页）/ 还原并落库（会员页）
4. **分享分级**：非会员只见海报，服务端裁剪，F12 也拿不到坐标
5. **成本控制**：高德缓存 30 天 + Key 池 + 排序用最近邻近似

## 13. 面试问题准备（基于真实经历）

1. **"你怎么保证接手一个半成品项目不把它改坏？"**
   → 备份 + 基线 tag + 只读审计(G1) + 代码地图(G2) + 现状核对(G3) + 每任务 diff/测试/回滚(G6)
2. **"举一个你发现的隐蔽 bug"**
   → 保存点位 delete-then-insert 无事务：insert 失败会清空用户路线；用故障注入（非法 place_id）复现，改成单事务 RPC + 唯一约束
3. **"怎么验证权限没配错？"**
   → 用 anon key 真打 8 张敏感表（0 行 vs 实际 1326 行作对照）；RPC 撤权后匿名调用 401
4. **"移动端适配你踩过什么坑？"**
   → 不是媒体查询问题，是 grid min-width:auto 导致整页缩放 27%；用 visualViewport 与 innerWidth 的差异定位
5. **"你怎么防止 AI 给出错误结论？"**
   → 证据分级、独立复核、只读理解闸门；实例：104 城的误报被拦下
6. **"没有 CI 怎么保证质量？"**
   → 本地四件套：`typecheck` + `test:run`(33) + `test:e2e`(8) + `audit:mobile`；每条任务卡带验收标准与回滚
