# 全库「水体风险」扫描报告

> 2026-10-25 17:40 · 脚本 `Project/scripts/scan-water-risk.mjs`（`npm run scan:water`）· 只读

## 方法

1. 取全部 `geo_status=matched` 且有坐标的地点（**1348 条**）
2. 对每条用高德 `place/text`（`citylimit=true` + 城市 adcode + 与线上相同的 `adcodeWithin` 过滤与打分规则）取同城候选
3. 计算「库内坐标」到「打分后最佳 POI」的距离；并找出**离库内坐标最近的 POI**
   - 最近 POI 距离 < 60m 且类型属于水体（海湾/河流/湖泊/海域/水库/海峡/滩涂/湿地）→ **判定点在水面上**
4. 距离 > 500m 记为「位置偏差」（仅提示，不自动改）

## 结果

| 项 | 数量 |
|---|---|
| 评估完成 | **1345** |
| 无同城结果 | 2 |
| 接口失败（重试后） | 1 |
| **落在水体 POI 上** | **0** |
| 位置偏差 > 1km | 36 |
| 位置偏差 500m–1km | 6 |

### 结论

- **全库已无"点漂在水面上"的记录**（南门湾已在此前修复）
- 42 条"位置偏差"绝大多数是**同名不同地点**造成的噪声：
  - `观景平台` / `观景台` / `湖心岛` 这类泛称，高德会返回别处的同名 POI
  - 例：西安「兵马俑」库内 109.282/34.386（正确），脚本建议 108.944/34.261（"直通车乘车点"，错误）
  - 例：大连「福禄面庄」建议 "福禄考"（67km 外的花圃），明显误配
- 因此这 42 条**不建议自动改**；若人工复核，优先看名称非泛称且偏差 >5km 的条目

## 已知限制

- 水体判定依赖「最近 POI 的类型」，若高德对某水体没有独立 POI（或类型标注为风景名胜），不会命中
- 建议值只作参考：同名泛称场景下可能比现状更差
- 扫描 1348 条约需 10–15 分钟（并发 2 + 限流重试 + Key 轮换）
