### 4.3 降级与「故意不做」

- **高德额度熔断**：用量 ≥80% 黄色预警，≥95% 红色预警；只有「所有 Key 都达 95%」才整体降级为直线估算，单 Key 用满只跳过该槽位。
- **排序兜底**：拿不到高德距离矩阵时，退回 cos 校正后的直线距离排序。
- **分享链接抓取失败**：静默回退到「用标题内容 + 提示用户粘贴正文」，接口返回 `linkReadFailed` 标记。
- **长图不调高德静态图**：纯 Canvas 自绘，避免额外配额。
- **周边知名地点默认懒加载**：用户主动点击才请求。
- **不做定时任务**：会员到期采用惰性判定（访问时比对 `member_until`），无需定时回落。
- **收款码人工核销**：不接支付网关，管理员手动开通；管理员手动开通的会员不计入付费订单。

### 5.3 计数机制（实现细节，务必别改坏）

- 计数表：`public.user_daily_usage(user_id, day, kind, count)`，主键含 `day + kind`；只有 service_role 能调 `get_user_daily_usage` / `bump_user_daily_usage`。
- **双周期桶**：
  - 免费用户按天 → `kind = 'generate_route'`，`day` 存服务器本地日期 `YYYY-MM-DD`
  - 会员按月 → `kind = 'generate_route_month'`，`day` 复用同列存 `YYYY-MM-01`
  - AI 提取按天 → `kind = 'ai_extract'`
- 周期口径由 `TierLimits.routeLimitPeriod`（`'day' | 'month'`）决定，取值在 `lib/member-quota.ts`。
- 会员的月度计数**不会**污染按天桶（实测确认）。

### 5.4 游客限流

- 桶：`city-places` / `order` / `import` / `ai-extract`，默认 **3 次/日**（`GUEST_TRY_RATE_LIMIT_PER_DAY`）。
- 有代理头取真实 IP；无代理头回落 `tfl_guest` cookie（HttpOnly，32 位 hex）。
- 游客草稿只存 `sessionStorage`，关页面即归零；游客导入的地点**不落库**，仅与库内地点合并参与勾选与排序。
- 游客态顶部工具栏**全部置灰去链接**（含 logo），移动端底部导航同样置灰；账号区显示「游客模式」+「登录 / 注册」。

## 八、已知问题与教训

### 8.1 本轮（10-19 / 10-20）新增

| 编号 | 教训 |
|---|---|
| L25 | 自建 Supabase 的 `/pg/query`（可执行任意 DDL）：**`apikey` 必须传 service_role**，用 anon 作 apikey 会返回「RBAC: access denied [403]」。纯数据读写仍走 PostgREST（`/rest/v1/表名` + `apikey` + `Authorization: Bearer <service_role>`）。 |
| L26 | cookie 里的 `sb-192-auth-token` 是二进制压缩态、解不出 `access_token`；要拿 JWT 请直接 `POST /auth/v1/token?grant_type=password`（带 apikey anon）。 |
| L27 | **Next.js App Router 的 fetch Data Cache 会缓存 supabase-js 的 GET 查询**（缓存键是长期不变的 URL），导致服务端第二次起永远读旧数据，会让用量看板、95% 熔断、地理编码缓存等省额度功能**静默失效**。所有服务端 Supabase 客户端必须注入 `global.fetch = noStoreFetch`。 |
| L28 | `supabase-js` 默认**没有超时**：Supabase 服务端假死时请求无限挂起、无任何报错。已在 `lib/supabase/fetch.ts` 用 `AbortController` 实现 `SUPABASE_TIMEOUT_MS=5000`（兼容 Edge runtime）。 |
| L29 | 自建 Supabase 假死的症状：TCP 到宿主机 8000/5432 秒级握手成功（3ms）但 HTTP/Postgres 一个字节都不回。**排查法**：对比「不查库的页面（`/login` 秒回 200）」与「查库的页面（`/city` 挂死）」，故障面精确等于 Supabase 服务端即可判定；不要误判成密码错 / 前端故障 / 网络不通。恢复：宿主机重启 Docker Desktop 或 `docker compose restart/up -d`。 |
| L30 | 心跳上报必须**单页只保留一个定时器、间隔 ≥30 秒、禁用 keepalive**，否则在 Safari 中会耗尽连接池导致页面打不开。 |
| L31 | 高德 `setFitView` 在小尺寸容器会抛 `Pixel(NaN, NaN)`，触发 React 错误边界 → **整页所有点击失效**。需单独兜底，且不要在卡片缩略图里用自动缩放。 |
| L32 | 小红书 / 抖音分享链接存在登录墙，服务端匿名抓不到正文。**主路径是让用户复制正文粘贴**；链接与文案混输时要先合并再识别，抓取失败必须有明确提示（`linkReadFailed`）。 |
| L33 | 高德导航起点与终点均为住宿点、且方式为步行 / 骑行时，可能触发高德「起点与终点太近」；驾车场景一般无此问题。地点过多还可能超出途经点数量上限，需准备逐段导航兜底。 |
| L34 | 高德个人认证 Key 有 QPS 限流：请求要串行、间隔 ≥350ms、失败要有退避重试。 |
| L35 | 高德 Web 服务 Key **开启数字签名会导致所有服务端调用被拒**；要么关闭，要么配置对应私钥签名。 |

### 8.2 v4 已记录的教训（沿用，仍适用）

L1 执行 `npm run build` 会覆盖 `.next` 并打断正在运行的 dev server → **本项目禁止 `npm run build`，只用 `npx tsc --noEmit` 验证**。
L2 `.env.local` 必须与 `package.json` 同层，否则所有页面 500。
L3 境外 Supabase 域名在国内宽带会被连接重置 → 必须迁国内（硬性要求）。
L4 登录失败提示要区分「连接失败 / 邮箱未确认 / 密码错误」。
L5 自建 Supabase 默认不发确认邮件 → 注册会出现确认邮件失败，需开启自动确认用户。
L6 修改 Docker Compose 的 `.env` 后必须 `docker compose up -d` 重建容器，重启容器不读新值。
L7 Envoy 网关 401 是 Basic 认证拦截，**不要误判为服务未启动**；优先查浏览器缓存的认证凭据。
L8 Windows 默认拦截 ICMP，判断自建 Supabase 是否在线要探测 8000 端口 HTTP 响应，别用 ping。
L9 墨刀 MCP 是生成型工具，不能读已有原型；下载需手动。
L10 墨刀原型本身含可复用的 Tailwind 类名与结构，要当「施工图」逐页对照，不能自行设计。
L11 跨表按名称关联时必须同时限定城市 / 归属条件，否则历史同名数据会重复插入。
L12 墨刀示例数据（城市 / 地点 / 路线）要导入数据库留存为测试数据。
