## 五、自建 Supabase 的形态与接线

### 5.1 形态

用户采用**官方 docker-compose 自建版**，那台 Windows 机上**没有 `supabase` 命令**（不需要安装 CLI）。端口：**8000 = 网关**（REST、Auth 与 Studio），**5432 = Postgres**。网关实际是 **Envoy**（非 Kong）。Studio 入口 `http://192.168.1.11:8000/`，需 basic-auth（值在 Windows 机 `supabase/docker/.env` 的 `DASHBOARD_USERNAME` / `DASHBOARD_PASSWORD`）。**改这两个值必须 `docker compose up -d` 重建容器**（L15）。

### 5.2 地址与端口

| 角色 | 地址 |
|---|---|
| 数据库主机（Windows 笔记本，常开） | `192.168.1.11`（不回 ping 属正常） |
| Mac（开发机） | `192.168.1.12`，同一 WiFi |
| 应用连接地址（`NEXT_PUBLIC_SUPABASE_URL`） | `http://192.168.1.11:8000` |
| REST 接口 | `http://192.168.1.11:8000/rest/v1/` |
| Auth 接口 | `http://192.168.1.11:8000/auth/v1/` |
| Studio 后台 | `http://192.168.1.11:8000/`（需 basic-auth） |

### 5.3 密钥

- Mac 侧 `Project/.env.local` 的两个 key 来自 Windows 机 `supabase/docker/.env` 的 `ANON_KEY` / `SERVICE_ROLE_KEY`（JWT 格式）。**不要在对话中回显**。
- 自建版默认密钥仅可用于局域网开发；阶段 ⑨ 上线前必须重新生成。

### 5.4 局域网通路（已实测可用，2026-10-17）

Mac → REST/Auth/Postgres 全通；注册/登录接口实测通过；Studio 网关 basic-auth 实测 307 放行。**不需要 Tailscale、不需要改防火墙**（Docker Desktop 已把端口发布到局域网）。

| 编号 | 教训 |
|---|---|
| L1 | 登录失败分三类提示（连不上后端 / 邮箱未确认 / 密码错误），不要统一显示「邮箱或密码不正确」 |
| L2 | 人工抄写 key/ref 一律用复制按钮（云端已弃用，仅归档） |
| L3 | 本机网络对 `*.supabase.co` 做 TLS 重置 → 改用局域网自建的根因，不要再尝试直连云端 |
| L4 | Node 不使用系统代理 |
| L5 | Windows 防火墙默认不回 ping；定位改用"直接探端口" |
| L6 | 自建版没有 `supabase` CLI，端口 8000/5432，不是 54321/54323 |
| L7 | 自建版未配 SMTP 时官方 `signUp` 会报 `Error sending confirmation email`；已用 `admin.createUser` 绕过（L13） |
| L8 | Docker Desktop 默认已把端口发布到局域网，先实测再动手 |
| L9 | Trae 沙箱内网络不可用；跨网测试走 `osascript` |
| L10 | "文件被用户删除"可能是误报；先 `git status` 或直接读文件核实 |
| L11 | `apply_all.sql` 头部注释要与实际包含的迁移范围一致 |
| L12 | 验证触发器用**行为测试**，不要只查 `pg_trigger`（PostgREST 读不到） |
| L13 | 自建版无 SMTP 也能注册：`auth.admin.createUser({ email_confirm: true })` + `signInWithPassword`；上线后改回邮箱确认 |
| L14 | zsh 里 `UID` 是内置变量，脚本变量名避开它 |
| L15 | 改 `supabase/docker/.env` 必须 `docker compose up -d` 重建容器（`restart` 无效） |
| L16 | `docker compose` 必须在含 `docker-compose.yml` 的目录执行；可用容器标签反查工作目录 |
| L17 | 自建版网关是 Envoy（看响应头 `server: envoy`），不是 Kong |
| L18 | **`next dev` 运行时跑 `npm run build` 会覆盖 `.next` 导致页面 500**；构建前先停 dev |
| L19 | **墨刀原型是含状态与交互的高保真可点击 Tailwind 页面，不是摘要参考**。把它当施工图：DOM/类名/文案逐字对齐；只做"静态页 + 自己理解"会被用户判定为不还原（2026-10-17 真实踩坑，17 页返工） |
| L20 | 原型文案进入 `messages.ts` 时**新开 M 码段、逐字搬运**，不要复用语义相近的旧 M 码（"没有匹配的城市"≠"没有找到"关键词""） |
| L21 | lucide-react 并非全量覆盖 mdi 图标；替换前先确认图标存在（`MapPlus` 在该版本不存在，用 `MapPinPlus`） |
| L22 | **高德个人认证 Key 并发很低**：连续突发调用返回 `infocode 10021 CUQPS_HAS_EXCEEDED_THE_LIMIT`，表现为「切一次出行方式就有几段算不出路线」。解决：所有高德请求走**模块级串行队列**（间隔 ≥350ms）+ 限流退避重试；单段仍失败则按直线距离×方式速度兜底 |
| L23 | **`route_places` 的保存接口是「先删后插」且无事务**：一旦提交的清单比真实地点少一条，那个地点就从路线里永久消失（2026-10-18 实测丢过「蜀九香火锅」）。解决：前端回写前校验「页面渲染地点数 == `route_places` 记录数」，不等则拒写并提示刷新 |
| L24 | 高德照片地址部分给的是 `http://`，在 https 站点会成为**混合内容被浏览器拦掉**（表现为缩略图空白）。解决：入库/返回前统一转 `https://` |
